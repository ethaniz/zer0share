# 请求缓存二阶段实施与验证

验证日期：2026-11-17（Asia/Shanghai）。

## 实施范围

- 保持请求驱动，没有调度、全市场请求或隐式全历史请求。
- 新增 `stk_limit`、`stock_st`、`suspend_d` 请求缓存；事件支持远程分页和同日多条记录。
- 新增单只 A 股日频 `pro_bar`，支持前后复权、均线、换手率和量比。基础接口按需缓存，派生结果不重复落库。
- 提供 `zer0share.tushare` 业务接入入口，调用方式见查询指南。
- 支持接口级近期、历史、空结果和快照有效期；局部刷新会拆开旧覆盖区间，防止旧的长期覆盖掩盖新的有效期。
- 显式导入旧股票 Parquet 分区，缺失或空分区不认证覆盖，不替换已有缓存。
- 提供命中与调用指标、按接口/股票/日期清理、一致性备份；缓存结构版本 1 自动事务升级为 2。

## 使用边界

- `pro_bar` 当前仅支持 `asset="E"`、`freq="D"`，要求具体单只股票及显式起始日期。前复权以请求区间内最新因子为基准；均线不额外拉取区间前的数据。
- 业务代码需显式改为使用项目提供的入口，不会自动拦截其他代码对外部 `tushare` 包的调用。
- 旧数据迁移目前覆盖六个股票日期接口，未扩展到快照、日历及其他资产。
- 缓存操作使用 macOS/Linux 本地文件锁，同一数据库保守串行。
- 凭证仍保存在 Git 忽略的 `config/settings.toml`，文件权限为 `600`。报告不包含凭证。
